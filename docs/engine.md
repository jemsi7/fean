# FEAN 엔진: 컴파일, 중간표현, 실행기

엔진은 [FEAN 형식언어](financial-language.md)로 쓴 모델 글을 받아 **실행 전에** 중간표현(이미지)으로 컴파일하고, 그 이미지를 실행해 질의 결과를 낸다. 흐름은 코드 입력 → 엔진 → AOT 컴파일 → 출력이다. 언어의 의미는 언어 명세가 정하고, 이 문서는 이미지의 형식과 실행기가 그 의미를 어떻게 실현하는지를 정한다.

<a id="pipeline"></a>
## 1. 흐름

```text
모델 글(.fean) ─ 구문 분석 ─ 전개 ─ 타입·구조 검사 ─ 하강 ─ 검증 ─▶ 이미지(.feanc)
이미지(.feanc) ─ 검증 ─ 매개변수 배정 ─ 이력 열거 ─ 질의 평가 ─▶ 결과
                              └ 역산 질의: 후보마다 사례를 세워 이력 열거와 목표 평가를 되풀이한다
```

| 단계 | 하는 일 | 위치 | 실패하면 |
|---|---|---|---|
| 구문 분석 | 글을 구문 나무로 읽는다 | [fean/syntax.py](../fean/syntax.py) | `S-Lex`, `S-Parse` |
| 전개와 검사 | 틀·절차·매개변수를 펴고 언어 명세 2절의 규칙을 적용한다 | [fean/static.py](../fean/static.py) | `T-*`, `E-*`, `W-*`, `P-*`, `Q-*` |
| 하강 | 검사된 모델을 이미지로 낮춘다 | [fean/lower.py](../fean/lower.py) | 실패하지 않는다 |
| 검증 | 이미지가 온전한지 본다 | [fean/ir.py](../fean/ir.py) | `I-*` |
| 실행 | 이미지를 실행해 질의를 평가한다 | [fean/vm.py](../fean/vm.py) | `D-*`, 배정에 달린 `W-Range`·`W-Clock`, 미판정 |

**미리 정하는 것과 실행 때 정하는 것.** 컴파일은 실행 전에 정할 수 있는 것을 모두 정한다. 이름은 번호가 되고, `def`와 평가값은 쓰인 자리에 펴지고, 틀과 절차는 기본 선언으로 전개되고, 식은 스택 기계 코드가 되고, 타입·단위·층·쓰기 권한은 검사를 마친다. 실행기에 남는 것은 값에 달린 일뿐이다. 공개 매개변수의 배정, 초기 세계의 열거, 조건과 재원의 판정, 이력의 열거, 시야와 지식, 질의의 평가다. 의미를 바꾸는 최적화는 하지 않는다.

## 2. 사용법

저장소 뿌리에서 실행한다. Python 3.13 표준 라이브러리만 쓴다.

```bash
python3 -m fean compile examples/repay80.fean
```

```bash
python3 -m fean run examples/repay80.feanc
```

```text
examples/repay80.fean → examples/repay80.feanc  (셀 5, 사건 6, 코드 블록 40, 질의 10)

possible = {early=false: true, early=true: true}
always   = {early=false: false, early=true: false}
canD     = {true}
knowsD   = {true}
knowsJ   = {false, true}
knowsL   = {}
laterD   = {early=false: true, early=true: true}
creditor = {early=false: true, early=true: true}
worst    = {early=false: 0[KRW], early=true: 100[KRW]}
chance   = {early=false: 1/2, early=true: 1}
```

| 명령 | 하는 일 |
|---|---|
| `compile 글 [-o 이미지]` | 글을 컴파일해 이미지 파일을 쓴다. `-o`가 없으면 글 파일과 같은 자리의 `.feanc`다 |
| `run 경로 [--json] [--budget N]` | 확장자가 `.feanc`이면 이미지로, 아니면 글로 읽어 컴파일한 뒤 실행하고 질의와 역산 질의마다 `이름 = 값`을 출력한다 |
| `dump 이미지` | 이미지의 표와 코드를 사람이 읽을 목록으로 출력한다 |
| `check 글` | 구문과 규칙만 검사한다 |

- 글의 자리에 `-`를 쓰면 표준입력을 읽는다. 이때 `compile`은 `-o`가 필요하다.
- 표준 계약([언어 명세 6절](financial-language.md#library))은 [fean/prelude.fean](../fean/prelude.fean)에 실려 있고 모든 글 앞에 놓인다. `--no-prelude`는 이를 뺀다.
- 결과의 표기는 언어 명세의 `// =>` 주석과 같다. `--json`은 같은 값을 한 개의 JSON 객체로 낸다. `--budget`은 관찰 지점 수의 한도이고 넘으면 그 결과는 `UNKNOWN`이다.
- 오류는 표준 오류에 `경로:줄: [규칙] 메시지`로 쓴다. 줄을 모르면 `경로: [규칙] 메시지`다. 오류가 나면 이미지 파일을 만들지도 고치지도 않는다.

| 종료 코드 | 뜻 |
|---|---|
| 0 | 성공. `UNKNOWN`이 섞여 있어도 0이다 |
| 1 | 컴파일 오류. 구문, 정적 규칙, 손상된 이미지 |
| 2 | 모델 실행 오류. `D-Init`, `D-Move`, `D-Weight` |
| 3 | 읽을 수 없는 입력 또는 잘못된 사용법 |

같은 일을 하는 함수는 [fean/\_\_init\_\_.py](../fean/__init__.py)에 있다.

```python
import fean

image = fean.compile_source(text)          # 글 → 검증된 이미지
open('m.feanc', 'w').write(fean.dumps(image))
results = fean.run_image(fean.loads(open('m.feanc').read()))   # {질의 이름: 결과 글}
```

## 3. 이미지의 표

이미지는 JSON 객체 하나다. 열쇠를 정렬하고 공백 없이 적으므로 같은 글은 바이트까지 같은 파일이 된다. `format`은 `feanc`, `version`은 2, `language`는 컴파일한 언어의 판(`0.3`)이다. 형식 1은 미지수와 역산 질의가 없던 판이며 읽지 않는다.

| 표 | 내용 |
|---|---|
| `model`, `language` | 모델 이름, 언어의 판 |
| `actors`, `enums`, `time` | 구성원 이름, 열거형과 그 값의 이름, 공개 시각의 처음과 끝 |
| `params` | 공개 매개변수. 이름, 종류, 가능한 값, 결과에 적을 글 |
| `unknowns` | 미지수. 이름, 종류(`bool`·`enum`·`time`·`actor`·`num`), 값의 범위 `lo`·`hi`. 열거값·구성원·참거짓도 번호로 적는다 |
| `cells` | 선언된 셀. 이름, 값의 영역, 빈 값 허용 여부, 범위의 코드, 초기값들의 코드 |
| `assets` | 자산. 이름, 보유 범위의 코드, 구성원마다의 초기 보유량 코드 |
| `slots` | 기억 슬롯. 소유 구성원, 열쇠, 내용의 영역 |
| `obs`, `mems` | 구성원마다 시야에 들어가는 셀 번호와 슬롯 번호의 목록 |
| `assumes`, `invariants` | 초기 세계의 제약과 불변식의 코드 |
| `events` | 사건. 이름, 매개변수 수, 지역 칸 수, 순액 여부, 조건·효과·사후 블록의 코드 |
| `units` | 커밋 단위. 구성원 사건과 그 인수의 코드, 순액 여부 |
| `blocks`, `entry` | 프로그램의 블록 표와 시작 블록 |
| `menus`, `marks`, `actions` | 메뉴, 지점 이름, 행동의 이름 |
| `weights` | 가중치의 이름과 코드 |
| `queries` | 질의. 이름, 단위 글, 종류와 코드 |
| `solves` | 역산 질의. 이름, 꼴(`find`·`any`·`min`·`max`), 지점의 번호 또는 없음, `where`·목적식·목표의 코드, 목적식의 단위 글 |
| `codes` | 코드 블록. 층, 지역 칸 수, 명령의 목록 |

**번호.** 이미지 안의 참조는 모두 번호다. 셀 번호는 선언된 셀이 먼저이고 보유량이 뒤따른다. 보유량 `bal(i, x)`의 번호는 `셀 수 + x의 번호 × 구성원 수 + i의 번호`다. 값은 정수, 참·거짓, `null`(빈 값)이다. 열거값은 그 열거형 안의 번호, 구성원은 구성원 번호, 시각과 수량은 정수다. 이름이 남는 곳은 사람에게 보일 표(이름, 결과의 글, 거절 사유)뿐이다.

| 언어 명세의 것 | 이미지에서 |
|---|---|
| `contract`, `instance` | 사라진다. `c.remain` 같은 이름의 셀과 사건이 된다 |
| `proc`, `do` | 사라진다. 부른 자리의 블록이 된다 |
| `def`, `value` | 사라진다. 쓰인 자리의 코드에 펴진다 |
| 행동의 매개변수 | 값마다 하나의 행동 이름(`bid(2)`)과 블록이 된다 |
| `param` | 남는다. 실행기가 값을 배정하고 코드는 `PARAM`으로 읽는다 |
| `unknown` | 남는다. 값은 정해지지 않은 채이고 코드는 `UNK`로 읽는다. 값은 역산 질의를 풀 때 후보마다 들어온다 |
| `solve` | `solves`의 한 항목. 목표 안의 질의 이름은 `QUERY`가 된다 |
| 범위, 초기값, 인수, `at`의 시각 | C층 코드로 남는다. 매개변수에 달릴 수 있기 때문이다 |
| 사건 | 지역 칸을 함께 쓰는 조건 블록(G), 효과 블록(E), `ensure`마다의 사후 블록(P) |
| `run`, `attempt`, `batch` | 커밋 단위의 번호 |
| 프로그램의 블록 | `blocks`의 한 항목. 문장은 `at`, `run`, `attempt`, `alt`, `choose`, `mark` |
| `at(ℓ, e)`, `K(i, φ)`의 안쪽 | 따로 떨어진 Q층 코드 블록 |

## 4. 코드 블록과 명령

코드 블록은 층 하나에 속한다. 층은 언어 명세 2.2의 일곱에 사건의 두 블록을 더한 아홉이다. 블록이 끝났을 때 스택에 남는 값의 수가 층마다 정해져 있다.

| 층 | 쓰는 곳 | 끝에 남는 값 |
|---|---|---|
| C 상수 | 범위, 초기값, 인수, `at`의 시각 | 1 |
| S 상태 | `assume`, `invariant`, `weight` | 1 |
| P 사후 | `ensure` | 1 |
| Q 지점 | `at`과 `K`의 안쪽 | 1 |
| R 이력 | 질의의 몸 | 1 |
| G 조건 | 사건의 `let`·`given`·`require`·`auth` | 0 |
| E 효과 | 사건의 효과 | 0 |
| V 목표 | 지점 없는 역산 질의의 목표와 목적식 | 1 |
| X 지점 목표 | 지점이 있는 역산 질의의 목표와 목적식 | 1 |

지점 없는 역산 질의의 `where`는 C층, 지점이 있는 것의 `where`는 S층 코드다. 명령은 `[이름, 인수…]`다. “상태”는 S·P·Q·G·E·X층을 뜻한다.

| 명령 | 인수 | 스택 | 층 | 뜻 |
|---|---|---|---|---|
| `PUSH` | 값 | → v | 모두 | 상수를 넣는다 |
| `PARAM` | 매개변수 | → v | 모두 | 공개 매개변수의 값 |
| `LOCAL` | 칸 | → v | 모두 | 지역 칸의 값 |
| `STORE` | 칸 | v → | 모두 | 지역 칸에 넣는다. `let`과 펴진 `def`의 인수에 쓴다 |
| `DUP` | | v → v v | 모두 | 맨 위 값을 하나 더 |
| `POP` | | v → | 모두 | 맨 위 값을 버린다 |
| `LOAD` | 셀 | → v | 상태 | 셀의 현재 값 |
| `BAL` | 자산 | i → v | 상태 | 구성원 i가 가진 그 자산의 보유량 |
| `NOW` | | → t | 상태 | 공개 시각 |
| `MEM` | 슬롯 | → v | 상태 | 슬롯의 내용. 비어 있으면 빈 값 |
| `ASOF` | 슬롯 | → t | 상태 | 슬롯의 사실 기준시각 |
| `RECV` | 슬롯 | → t | 상태 | 슬롯의 수신시각 |
| `POST` | 셀 | → v | P | 후상태 후보의 셀 값 |
| `ADD` | | a b → a+b | 모두 | 덧셈 |
| `SUB` | | a b → a−b | 모두 | 뺄셈 |
| `MUL` | | a b → a·b | 모두 | 곱셈 |
| `MIN` | | a b → v | 모두 | 작은 쪽 |
| `MAX` | | a b → v | 모두 | 큰 쪽 |
| `DIVF` | | a b → v | 모두 | 내림 나눗셈. b가 0이면 빈 값 |
| `DIVC` | | a b → v | 모두 | 올림 나눗셈. b가 0이면 빈 값 |
| `DIVX` | | a b → v | 모두 | 나누어떨어질 때만 몫, 아니면 빈 값 |
| `EQ` | | a b → 참·거짓 | 모두 | 같다. 빈 값끼리는 같다 |
| `NE` | | a b → 참·거짓 | 모두 | 다르다 |
| `LT` | | a b → 참·거짓 | 모두 | a < b |
| `LE` | | a b → 참·거짓 | 모두 | a ≤ b |
| `GT` | | a b → 참·거짓 | 모두 | a > b |
| `GE` | | a b → 참·거짓 | 모두 | a ≥ b |
| `NEG` | | a → −a | 모두 | 부호 바꿈 |
| `NOT` | | a → 참·거짓 | 모두 | 부정 |
| `KNOWN` | | v → 참·거짓 | 모두 | 빈 값이 아니다 |
| `JMP` | 자리 | | 모두 | 그 자리로 간다 |
| `JF` | 자리 | v → | 모두 | 거짓이면 그 자리로 간다 |
| `JT` | 자리 | v → | 모두 | 참이면 그 자리로 간다 |
| `K` | 구성원, 코드 | → 참·거짓 | Q | 그 구성원이 현재 지점과 구별하지 못하는 모든 지점에서 코드가 참이다 |
| `AT` | 지점 종류, 번호, 코드, 불 여부 | → v | R | 이력이 그 지점을 지나면 거기서 코드를 실행한 값. 지나지 않으면 불 여부가 참일 때 거짓, 아니면 빈 값 |
| `REACH` | 지점 종류, 번호 | → 참·거짓 | R | 이력이 그 지점을 지난다 |
| `REQUIRE` | 사유 | v → | G | 거짓이면 이 커밋을 `BLOCKED`로 끝낸다 |
| `GIVEN` | 칸, 사유 | v → | G | 빈 값이면 `BLOCKED`, 아니면 지역 칸에 넣는다 |
| `FXSET` | 셀 | v → | E | 대입을 커밋 버퍼에 쌓는다 |
| `FXADD` | 셀 | v → | E | 증감을 쌓는다. 보유량이면 생성·소멸로 센다 |
| `FXFREE` | 셀 | | E | 그 셀을 미정으로 둔다 |
| `FXMOVE` | 자산 | 보내는 이, 받는 이, n → | E | 이전을 쌓는다. n이 음수면 `D-Move` |
| `FXTELL` | 슬롯 | v, 기준시각 → | E | 수신을 쌓는다. 수신시각은 현재 시각이다 |
| `FXFORGET` | 슬롯 | | E | 망각을 쌓는다 |
| `UNK` | 미지수 | → v | 모두 | 미지수의 값. 이 사례에 들어온 값이다 |
| `QUERY` | 질의 | → v | V, X | 그 질의의 이 사례에서의 판정. 불 질의면 참·거짓, 수치 질의면 수 |

지점 종류는 0 `start`, 1 `end`, 2 `menu`, 3 `label`이다. 2와 3은 메뉴와 지점 이름의 번호를 함께 적는다.

**표면 문법이 낮춰지는 모양.**

| 표면 | 코드 |
|---|---|
| `a and b` | a, `JF` ①, b, `JMP` ②, ① `PUSH false`, ② |
| `a or b` | a, `JT` ①, b, `JMP` ②, ① `PUSH true`, ② |
| `if c then a else b` | c, `JF` ①, a, `JMP` ②, ① b, ② |
| `e ?? d` | e, `DUP`, `KNOWN`, `JT` ①, `POP`, d, ① |
| `f(x, y)` | x, `STORE` k₁, y, `STORE` k₂, 이어서 f의 몸. 몸은 매개변수를 `LOCAL` k로 읽는다 |
| `bal(D, KRW)` / `bal(e, KRW)` | `LOAD` 보유량 번호 / e, `BAL` 자산 |
| `c -= e` | e, `NEG`, `FXADD` c |
| `move a -> b : n` | a, b, n, `FXMOVE` 자산 |
| `tell i.k := v asof u` | v, u, `FXTELL` 슬롯 |

`and`·`or`·`if`·`??`는 필요한 쪽만 실행한다. 식의 평가가 실패하지 않으므로 결과는 양쪽을 모두 계산한 것과 같다.

**예.** 언어 명세 7절의 `collect` 사건은 이렇게 낮춰진다. 왼쪽은 `dump`의 출력 그대로다.

```text
  c15 [G, locals 1]                            require life == active
        0 LOAD 4                  ; life
        1 PUSH 1
        2 EQ
        3 REQUIRE "require in collect"
        4 LOAD 5                  ; bal(D,KRW)       let b = min(bal(D, KRW), remain)
        5 LOAD 3                  ; remain
        6 MIN
        7 STORE 0
  c16 [E, locals 1]
        0 PUSH 0                                     move D -> L : b
        1 PUSH 1
        2 LOCAL 0
        3 FXMOVE 0                ; KRW
        4 LOCAL 0                                    remain -= b
        5 NEG
        6 FXADD 3                 ; remain
        7 LOCAL 0                                    life := if b == remain then settled else active
        8 LOAD 3                  ; remain
        9 EQ
       10 JF 13
       11 PUSH 2
       12 JMP 14
       13 PUSH 1
       14 FXSET 4                 ; life
```

## 5. 이미지 검증 규칙

이미지는 컴파일 직후에 한 번, 실행기가 읽을 때 다시 한 번 검증한다. 검증을 통과하지 못한 이미지는 실행하지 않는다. 그래서 손상되었거나 손으로 고친 파일이 실행기를 오동작시키지 못한다.

| 규칙 | 조건 |
|---|---|
| I-Format | 파일이 JSON이고 `format`이 `feanc`, `version`이 2다. 모든 표가 있고 모양이 맞다. 명령의 인수 개수와 상수의 종류가 맞다. 미지수의 범위는 정수이고 비어 있지 않으며, 역산 질의는 `min`·`max`일 때만 목적식이 있다 |
| I-Ref | 모든 번호가 그 표의 범위 안이고 정수다. 지역 칸은 블록의 칸 수 안이다. 사건의 세 블록은 칸 수가 사건과 같고, 커밋 단위의 인수 수는 사건의 매개변수 수와 같다. 안쪽 코드 블록의 번호는 바깥보다 작다. 프로그램의 블록은 시작 블록을 빼고 꼭 한 번씩 참조된다. `QUERY`가 가리키는 질의는 값이 하나다(영역 질의와 가중 기댓값 질의가 아니다) |
| I-Mode | 명령이 그 블록의 층에 허용된 것이다. 가리키는 코드 블록의 층이 그 자리에 맞다. 모르는 명령과 모르는 층은 없다 |
| I-Stack | 어느 경로로 가도 스택이 모자라지 않고, 경로가 만나는 자리의 깊이가 같으며, 끝에 4절의 표가 정한 수의 값이 남는다. 점프는 같은 블록 안에서 앞으로만 간다 |

점프가 앞으로만 가고, 안쪽 코드 블록의 번호가 바깥보다 작고, 프로그램이 나무이므로, 검증된 이미지의 실행은 반드시 끝난다.

## 6. 실행기

실행기는 글을 읽지 않고 타입을 검사하지 않는다. 언어 명세의 의미를 아래와 같이 실현한다.

| 언어 명세 | 실행기가 하는 일 |
|---|---|
| 3.1 상태와 초기 세계 | 상태는 (시각, 셀 값의 배열, 슬롯의 배열)이다. 매개변수 배정마다 범위와 초기값의 코드를 실행하고, 초기값 선택의 모든 조합에서 `assumes`를 만족하는 것을 세계로 삼는다 |
| 3.2 한 커밋의 판정 | 단위의 사건마다 인수 코드를 실행해 지역 칸에 넣고 조건 블록을 실행한다. `REQUIRE`·`GIVEN`이 실패하면 `BLOCKED`다. 이어서 효과 블록들이 커밋 버퍼를 채운다. 보유량마다 재원을 판정하고, 미정 셀을 영역에서 열거해 후보를 만들고, 쓴 셀의 범위와 `invariants`, 사후 블록으로 거른다 |
| 3.3 프로그램의 걸음 | 블록의 문장을 차례로 실행하며 걸음마다 관찰 지점을 하나 만든다. 가지가 갈리면 가지마다 나머지 프로그램을 이어 실행한다 |
| 4.1 이력과 관찰 지점 | 관찰 지점은 나무의 노드다. 뿌리에서 그 노드까지가 이력의 접두부다. 지점 선택은 경로에서 `init`·`show`·`mark`·`end` 걸음을 찾는다 |
| 4.2 시야 | (시각, 표시된 메뉴와 행동 목록, `mems`의 슬롯들, `obs`의 셀 값들) |
| 4.3 지식 | 구성원마다 시야가 같은 노드를 묶고, `K`는 그 묶음의 모든 노드에서 안쪽 코드를 실행한다 |
| 5 질의 | 언어 명세 5.2의 정의 그대로다. 정책은 연합 구성원의 (시야 → 행동) 표를 모두 열거한다 |
| 5.4 역산 | 후보마다 사례를 세운다. 사례는 매개변수와 미지수의 값이 모두 정해진 실행기다. 지점이 있으면 그 상태를 하나뿐인 초기 세계로 두고, 프로그램에서 그 `mark` 문장 바로 뒤(그 블록의 나머지, 이어서 바깥 블록들의 나머지)부터 실행한다. 이때 뿌리 노드는 `start`이자 그 지점이다. `where`를 통과한 후보에서 이력을 모두 열거한 뒤 목표 코드를 실행하며, `QUERY`는 그 사례에서 질의를 평가한 값이다(사례마다 한 번 계산한다). 실행 오류가 나면 그 후보는 해가 아니고, 탐색 한도를 넘으면 미판정이다 |

**후보의 좌표.** 후보는 정수의 열이다. 차례는 미지수, `now`, 선언된 셀, 보유량(자산, 구성원 순), 슬롯마다의 값·기준 시각·받은 시각이다. 빈 값을 가질 수 있는 셀과 슬롯의 값은 범위의 아래 끝보다 1 작은 수가 빈 값(슬롯은 ‘없음’)을 뜻하고, 없는 슬롯의 두 시각은 가장 이른 시각으로 둔다. 그래서 정수의 사전식 순서가 언어 명세의 순서와 같다. Python 엔진은 이 좌표를 하나씩 세어 가며 정의대로 답하고 후보가 200,000개를 넘으면 `UNKNOWN`을 낸다. 경계를 찾아 푸는 솔버는 Rust 엔진에 있다(8장).

판정과 거절 사유, 실행 오류의 이름, 탐색 한도와 `UNKNOWN`, 결과의 표기는 언어 명세와 같다. 값에 달려 실행 때 드러나는 `W-Range`·`W-Clock`은 배정마다 그 배정을 처음 쓸 때 난다.

## 7. 검증의 범위

엔진의 정확성 기준은 둘이다. 언어 명세의 `// =>` 기대 결과, 그리고 [참조 구현](../tests/fean_ref/__init__.py)과의 대조다. 참조 구현은 구문 나무를 직접 걷고 엔진은 이미지를 실행하므로, 둘이 같은 결과를 내면 하강과 실행기가 의미를 보존한 것이다. [엔진 검산](../tests/test_fean_engine.py)은 다음을 확인한다.

- 언어 명세의 모델 10개와 보조 모델 9개에서 질의 결과가 기대 결과 또는 참조 구현과 글자까지 같다.
- 같은 모델들의 모든 매개변수 배정에서 관찰 지점의 수와 걸음의 종류가 같고, 말단마다의 실패 종류·시각·모든 셀 값·모든 슬롯이 같다. 사건 하나씩의 커밋 판정과 거절 사유도 같다.
- 같은 글은 같은 바이트의 이미지를 내고, 파일로 썼다가 읽어도 같다.
- 5절의 규칙마다 그것을 어기게 망가뜨린 이미지가 거절된다. 미지수와 역산 질의의 표를 망가뜨린 이미지 15개도 맞는 규칙으로 거절된다.
- 역산 모델 16개(명세의 `Capital`·`Escrow`와 보조 모델 14개)에서 후보 13,253개 하나하나의 판정이 참조 구현과 같고, 대표 해·최적값·미판정 여부와 결과 글이 같다. 해에서 세운 사례 65개는 걸음의 열과 말단의 상태까지 같다. 보조 모델 가운데 여섯은 한 가지씩을 겨냥하며 그 답을 손으로 계산한 값과도 견준다. 후보가 한도를 넘을 때의 `UNKNOWN`과 탐색 한도 2·3·6·9에서 미판정으로 남는 후보도 같다.
- 지점에서 시작한 실행은 처음부터 실행한 이력에서 그 지점 아래에 놓인 부분과 같다. 두 구현에서 모두 40곳을 확인한다.

구문 분석과 타입 검사는 엔진과 참조 구현이 같은 코드를 쓴다. 그래서 대조가 확인하는 범위는 하강과 실행이다. 앞단은 [v0.2 검산](../tests/test_fean_v02.py)이 규칙마다 따로 확인한다.

이번 범위에 없는 것은 다음과 같다. 실행기의 속도는 참조 구현과 같은 차수이고 빠르게 하지 않았다. 네이티브 코드는 만들지 않는다. 프로그램의 걸음을 재귀로 따라가므로 한 경로가 수백 문장을 넘으면 Python의 재귀 한도에 닿을 수 있다. 이미지 형식의 판은 2 하나이고, 판 1의 이미지는 읽지 않고 `I-Format`으로 거절한다(다시 컴파일하면 된다). Python 엔진의 역산은 후보를 하나씩 세는 정의 그대로의 계산이라 범위가 넓으면 `UNKNOWN`이 된다. 넓은 범위는 Rust 엔진의 솔버가 맡는다(8장).

## 8. Rust 엔진과 IDE

같은 엔진이 Rust로도 있다. 컴파일과 실행을 빠르게 하고, 그 위에 IDE를 올리기 위해서다. 이 문서의 1~7장은 두 엔진에 똑같이 적용된다. 이미지의 형식이 같고, 같은 글에서 두 엔진이 내는 이미지 파일은 바이트까지 같다. Python 엔진이 기준이고 Rust 엔진은 그것과 대조해 검산한다.

| 부분 | 위치 | Python의 대응 |
|---|---|---|
| 구문 분석 | [rust/fean-core/src/syntax.rs](../rust/fean-core/src/syntax.rs) | `fean/syntax.py` |
| 전개와 검사 | [rust/fean-core/src/check.rs](../rust/fean-core/src/check.rs) | `fean/static.py` |
| 하강 | [rust/fean-core/src/lower.rs](../rust/fean-core/src/lower.rs) | `fean/lower.py` |
| 이미지와 검증 | [rust/fean-core/src/image.rs](../rust/fean-core/src/image.rs) | `fean/ir.py` |
| 실행기 | [rust/fean-core/src/vm.rs](../rust/fean-core/src/vm.rs), [session.rs](../rust/fean-core/src/session.rs) | `fean/vm.py` |
| 역산 솔버 | [rust/fean-core/src/solve.rs](../rust/fean-core/src/solve.rs), [sym.rs](../rust/fean-core/src/sym.rs) | `fean/vm.py`의 전수 역산 (같은 답, 다른 방법) |
| 실행 기록과 분석 | [rust/fean-core/src/trace.rs](../rust/fean-core/src/trace.rs) | 없음 (IDE를 위한 것) |
| 명령줄 | [rust/fean-cli/src/main.rs](../rust/fean-cli/src/main.rs) | `fean/cli.py` |
| IDE | [rust/fean-ide/src](../rust/fean-ide/src/main.rs) | 없음 |

**빌드.** `bash rust/build.sh`가 `dist/fean`(명령줄)과 `dist/fean-ide`(IDE)를 만든다. 표준 계약은 두 엔진이 [fean/prelude.fean](../fean/prelude.fean) 한 파일을 함께 쓴다.

**명령줄.** `dist/fean compile|run|dump|check`는 2장의 Python 명령줄과 입력, 출력, 종료 코드가 같다. 여기에 둘이 더 있다. `fean inspect PATH [--views]`는 IDE가 보여 주는 자료(질의와 근거, 모순, 사례와 그 이력·걸음, 거래 그래프, 원장, 주체의 지식, 역산 질의의 답과 영역)를 JSON으로 낸다. `fean batch`는 표준입력의 작업 목록을 한 프로세스에서 수행하며 검산이 쓴다. 역산을 위한 작업은 둘이다. `solve`는 역산 질의마다 답과 영역을 내고 지정한 후보들에서의 판정을 답하며, `case`는 후보 하나를 사례로 열어 그 이력을 낸다.

**Rust 엔진만의 것.** 결과를 바꾸지 않는 범위에서 다음이 다르다.

| 항목 | Python 엔진 | Rust 엔진 |
|---|---|---|
| 한 경로의 문장 수 | 인터프리터의 재귀 한도(1,000쯤)에 걸린다 | 한도가 없다. 프로그램을 작업 스택으로 실행한다 |
| 식과 블록의 깊이 | 재귀 한도에 걸리면 죽는다 | 2,000을 넘으면 `S-Parse`로 거절한다 |
| 수량의 크기 | 제한 없는 정수 | 64비트 정수. 넘치면 `D-Overflow`, 리터럴이 넘치면 `S-Lex` |
| 지식 판정 | 물을 때마다 계산한다 | (주체, 정보 집합, 코드)마다 한 번 계산한다 |
| 전략 탐색 | 모든 조합을 차례로 센다 | 어긋난 이력을 버리며 찾는다. 2,000,000걸음을 넘으면 그 질의는 미판정이다 |
| 셀의 정의역 | 값의 목록 | 범위 |
| 역산 | 후보를 하나씩 센다. 후보가 200,000개를 넘으면 `UNKNOWN`이다 | 결과가 갈리는 경계를 찾는다. 실행 10,000번을 넘으면 남은 영역이 미판정이다 |
| 좌표가 여럿인 `find`의 표기 | 해의 나열 `{(…), (…)}` | 조건의 묶음 `{[…], […]}` |

<a id="solver"></a>
**역산 솔버.** 언어 명세 5.4의 역산은 후보를 모두 넣어 보는 것으로 정의된다. Rust 엔진은 같은 답을 후보의 수가 아니라 **결과가 갈리는 경우의 수**만큼의 실행으로 낸다.

1. *기록하는 실행.* 솔버가 돌리는 실행기에서 값은 (수, 식의 꼴)의 쌍이다. 미지수와 지점의 좌표가 변수이고, 값은 그 변수들의 일차식을 지니고 다닌다. 식에 달린 판정(비교, 참·거짓, 범위와 재원의 검사, 두 값이 같은지)을 내릴 때마다 조건 `lo ≤ 식 ≤ hi`를 적는다. 한 번의 실행이 적은 조건을 모두 지키는 점에서는 실행이 같은 길을 가므로 판정(해, 해 아님, 후보 아님, 무효, 미판정)이 같다. 그 점들의 집합이 **영역**이다.
2. *분할.* 일감은 영역의 목록이고 처음에는 후보 전체다. 영역에서 점 하나를 골라 실행하면 그 실행의 영역이 잎이 되고, 조건을 차례로 하나씩 뒤집은 영역들(앞의 조건은 그대로, 그 조건만 반대)이 새 일감이 된다. 일감이 비면 잎들이 후보 전체를 겹치지 않게 덮는다.
3. *일차식이 아닌 것.* 상수로 나눈 몫 `floor(x / d)`는 보조 변수 q와 정의 조건 `0 ≤ x − d·q ≤ d − 1`로 둔다. 두 식의 곱(값의 가짓수가 적은 쪽), 식으로 나누기, 구성원 번호로 쓰인 값, 가중치와 가중치가 붙은 선호의 평가값, `free` 셀의 범위 끝은 그 실행의 값으로 고정한다(조건 `식 = 값`). 고정은 언제나 옳고, 그 값마다 실행이 따로 든다.
4. *정수의 한계.* 식의 값이 64비트를 넘을 수 있으면 넘지 않는다는 조건을 적는다. 넘는 쪽의 영역은 따로 실행되어 `D-Overflow`로 무효가 된다.
5. *지식.* 주체가 구별하지 못하는 지점의 묶음은 값에 달려 있다. 묶음을 이룬 같음과, 묶음들을 줄 세운 순서를 조건으로 적는다.
6. *정수 점 찾기.* 영역은 변수의 구간과 조건들이다. 구간을 조건으로 좁히고, 유리수 위의 소거로 빈 영역을 가려내고, 첫 변수부터 반으로 갈라 아래쪽을 먼저 본다. 그래서 처음 찾은 점이 사전식으로 가장 작다. 상자 20,000개를 열고도 정하지 못하면 미판정이다.
7. *결론.* `find`는 해인 잎을 적는다. 판정이 같고 맞닿은 잎은 합치고, 다른 조건이나 선언된 범위가 이미 말해 주는 조건은 지운다. 좌표가 하나이면 구간으로 훑어 `{80..200}`처럼 적는다(구간 2,000개까지). `any`는 해인 잎들의 첫 점 가운데 가장 작은 것이고, `min`·`max`는 잎마다 목적식의 최적값을 이분 탐색으로 찾아 견준다. 미판정인 잎이 답을 바꿀 수 있으면 `UNKNOWN`이다.
8. *자기 점검.* 적은 조건이 그 실행의 점에서 거짓이거나 값이 제 식과 어긋나면 그 역산은 답 대신 오류로 끝난다. 틀린 영역을 내지 않기 위해서다.

예를 들어 `Capital`의 `need = min cap: repaid`는 `cap` 0..200에서 실행 세 번으로 영역 `[cap <= 79]`(해 아님)와 `[cap >= 80]`(해)을 얻는다. 범위를 0..1,000,000,000으로 넓혀도 실행 횟수는 그대로다.

**사례.** 역산의 답에는 값이 따른다. 분석(`trace.rs`)은 역산 질의마다 대표 해와, 목표가 성립하지 않는 가장 작은 후보에서 모델을 실행해 **사례**로 둔다. 사례는 매개변수 배정과 같은 자리에 놓여 이력, 그래프, 원장, 지식을 똑같이 볼 수 있다. 미지수가 있는 모델의 사례는 이것들뿐이고, 일반 질의의 근거도 그 사례에서 찾는다. 사례에서 실패한 사건이나 거짓인 보장은 모순으로 치지 않는다. 해가 하나도 없는 역산 질의가 모순이다. 영역의 다른 값도 사례로 열 수 있다. 좌표의 수가 맞고 지점의 상태가 선언된 범위 안이어야 하며, 아니면 `I-Ref`로 거절한다.

**실행 기록.** `trace.rs`는 실행기가 만든 이력 나무에서 IDE의 보기를 만든다. 완결 이력마다의 걸음(종류, 시각, 낀 주체, 이전, 바뀐 셀, 통지, 사유, 코드의 줄), 재생 위치까지의 이전 합계, 주체별 원장과 잔액, 주체가 구별하지 못하는 지점들로부터의 지식, 이력이 갈리는 지점의 나무, 질의마다의 증인·반례·전략, 그리고 모순의 목록이다. 모순은 컴파일 오류, 실행 오류, 실패한 필수 사건, 거짓인 보장(`forall`, `can`)이다. 요소의 줄은 이미지에 넣지 않고 따로 든 소스 맵에서 얻는다. 이미지를 Python 엔진과 같게 두기 위해서다.

**IDE.** `dist/fean-ide`는 코드 편집기와 결과 보기를 한 창에 둔다. 사용법은 [설명서](manual/FEAN-IDE-설명서.pdf)([원본](manual/manual.html))에 있다. `fean-ide --shots DIR`은 정해진 시나리오를 스스로 수행하며 화면과 보고서를 남긴다. IDE의 검산과 설명서의 그림이 이 모드에서 나온다.

**대조 검산.** `tests/test_fean_rust.py`가 두 엔진을 맞댄다. 글 161개에서 앞단의 판정(오류 종류, 규칙 이름, 줄)이 같고, 모델 33개의 이미지와 목록이 바이트까지 같으며, 미지수가 없는 모델 18개의 모든 배정에서 관찰 지점 4,963개의 걸음과 말단의 상태, 결과 글 96개가 같다. 손상된 이미지 24개와 손상된 역산 표 15개가 같은 규칙으로 거절되고, 명령 36개에서 두 명령줄의 종료 코드·출력·이미지 파일이 같다. 실행 기록은 Python 실행기의 상태와 지식 묶음에 대조한다.

솔버는 정의(Python 엔진의 전수 역산)에 맞댄다. 역산 모델 23개(위의 16개와, 엔진 검산의 모델에서 매개변수를 미지수로 바꾸어 만든 7개)의 역산 질의 166개에서 후보 14,835개의 판정이 하나하나 같고 결과 글이 같다. 그 가운데 여섯은 솔버가 틀리기 쉬운 곳을 하나씩 겨냥한다. 두 미지수의 곱, 미지수에 달린 지식의 묶음, 미지수에 달린 `free` 셀의 범위, 나누는 수의 배수에서 갈리는 몫과 나누어떨어지지 않는 경계, 가중치가 붙은 평가값, 질의와 이름이 같은 미지수를 읽는 `def`다. 이 모델들은 솔버를 한 곳씩 일부러 깨뜨려 보는 변이 점검에서 기존 검산이 놓친 곳을 메우려고 둔 것이다. 지점의 상태는 작은 모델 셋에서 15,784개를 빠짐없이, 큰 모델 아홉에서 3,343개를 골라 대조하고, 이력이 지점에서 실제로 닿는 상태에서도 같음을 본다. 범위가 0..1,000,000,000인 모델 셋은 역산 질의마다 실행 10번 안에 풀리며, 그 답을 산술로, 후보 856개를 Python 엔진의 한 점 판정으로 확인한다. 64비트의 끝에 걸친 범위에서는 식이 넘치는 값이 무효로 빠지고 그 경계가 산술과 같다. 탐색 한도를 2·3·6으로, 실행 횟수 한도를 0~3으로 줄였을 때 솔버는 정하지 못한 후보를 미판정으로 남기고 틀린 판정을 내지 않는다.

**속도.** 미지수가 없는 모델 17개 기준으로 Python 엔진은 컴파일 16ms, 실행 32ms이고 Rust 엔진은 컴파일 4.5ms, 실행 1.0ms다(프로세스 시작 2.5ms 제외). 문장 50,000개가 한 줄로 이어진 프로그램은 0.08초에 실행된다. 역산은 `Capital`(범위 0..200, 역산 질의 넷)에서 Python 엔진이 23ms, Rust 엔진이 0.02ms이고, 범위가 0..1,000,000,000인 모델 셋은 Rust 엔진에서 0.04~0.2ms다(Python 엔진은 후보 한도를 넘어 `UNKNOWN`).
